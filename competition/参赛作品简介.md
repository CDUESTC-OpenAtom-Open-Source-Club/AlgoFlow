# AlgoFlow 算法随想 · 参赛作品简介

> 2026 开源鸿蒙大学生创新大赛 · 赛道三（方向一：开源鸿蒙创新应用开发并上架鸿蒙应用市场）
>
> 参赛团队：Chino 队

## 一句话介绍

手机记思路，电脑接着写；AI 帮你把自己的想法理清，不替你给答案。

## 为什么做

刷算法题时，灵感常出现在通勤、排队这些碎片时间，可手机上写不了代码，回到电脑前思路又忘了。现有 AI 工具往往直接给出标准答案，学习者失去了自己验证思路的机会。

AlgoFlow 让用户在手机上随手记下思路和代码，在电脑浏览器里接着编辑同一份草稿；AI 只把用户自己的想法整理清楚，不擅自替换成正确解法。

## 面向用户

- 算法竞赛选手
- 数据结构与算法课程的学生
- 准备技术面试的开发者

## 核心功能

| 功能 | 说明 |
| --- | --- |
| 手机代码编辑器 | 首屏即可编辑的 `main.cpp`，带行号、当前行高亮和等宽字体 |
| 手机与电脑同步 | 扫码或输入配对码连接电脑后双向同步；版本冲突保留两份副本由用户选择，不静默覆盖 |
| 思路片段 | 思路按行拆成带稳定编号的片段，AI 输出的每一步都能追溯到用户写的那一行 |
| AI 忠实转换 | 按原思路生成伪代码或 C++ 片段，并列出假设、缺失信息和风险，不偷偷补成正确解法 |
| 隐藏与复写对比 | 先隐藏 AI 结果独立复写，再按步骤对比遗漏与新增 |
| 桌面服务卡片 | 不打开应用即可查看最近草稿与同步状态，一键新建思路，点击直达对应草稿 |
| 离线优先 | 草稿与待同步操作保存在本地数据库，断网照常编辑，联网后再同步 |

## 创新点

- **思路优先，不给答案**：AI 默认只做忠实转换，即使思路有误也照实整理并标出风险；渐进提示与完整解题是独立模式，必须由用户主动选择，结果互不覆盖。
- **先自己写再对比**：AI 结果可以隐藏，独立复写后逐步骤比对，保留自主思考的过程。
- **跨端接力**：手机端是原生 ArkTS 应用，电脑端是浏览器工作台，两端共用同一套数据契约和同步协议。

## 接入的鸿蒙特性

- **服务卡片**：桌面卡片显示最近草稿标题与同步状态，只读本地快照，不展示代码正文。
- **ArkTS + ArkUI 原生开发**：Stage 模型；关系型数据库（RDB）保存草稿与离线队列，带显式版本迁移。
- **Scan Kit 扫码配对**：调用 HarmonyOS 系统扫码界面连接电脑，应用无需申请相机权限（HarmonyOS 专有能力，不支持的设备可手输配对码）。
- **ArkGuard 混淆**：Release 包启用代码混淆。

## 技术架构

```text
OpenHarmony / HarmonyOS 手机端（ArkTS + ArkUI）
             │
             ├── HTTP push/pull ── sync-api（同步、冲突、配对）
             │                    AI Gateway（契约校验、来源与版本门禁）
             │
浏览器桌面工作台（React + Vite + TypeScript + CodeMirror 6）
```

各模块与运行方式见仓库根目录 [README.md](../README.md)。

## 当前状态（如实说明）

- **应用市场版本仅本机可用**：不含云端服务，同步与 AI 需要用户自行提供可访问的端点；上架包不显示 AI 入口。
- **AI 演示**：演示视频使用 Debug 包和本地演示 Provider，不是真实模型输出。
- **验证范围**：手机端在 HarmonyOS 模拟器（Mate 70 Pro，API 20）上完成本地验证，尚未做真机验证。
- **同步**：普通 HTTP 同步，适合局域网联调；不是 OpenHarmony 分布式能力，也不是生产云同步。
