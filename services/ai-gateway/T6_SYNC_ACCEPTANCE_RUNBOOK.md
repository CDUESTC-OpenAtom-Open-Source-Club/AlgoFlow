# T6 接受后普通代码安全同步验收准备

本手册对应需求单 T6：接受局部补全后，只有普通 `main.cpp` 编辑进入草稿本地队列；AI 结果和隐藏状态不进入同步载荷。当前无手机设备，只交付工程准备和可重复回归，不标记 T6 设备验收通过。

## 验收边界

- 手机接受补全后只更新当前草稿并生成离线操作，不主动调用同步；用户点击同步或恢复在线后才发送。
- Web 与手机使用同一草稿 ID、`base_version`、`operation_id` 和同步游标；重复发送保持幂等。
- 并发版本不匹配必须保留服务器版本和本地冲突副本，由用户选择；不得静默覆盖。
- 同步请求期间继续编辑必须生成新的操作身份并保留较新本地内容；旧响应不得覆盖新编辑。
- 远端墓碑保留删除版本，并清理对应本地 AI 结果；AI 结果、会话历史和隐藏状态不进入同步载荷。
- 手机 pull 会拒绝低于本地已同步版本的旧变更；远端墓碑同时清理数据库结果和当前会话内存结果。

## 可执行准备验证

在仓库根目录执行：

```powershell
node --test apps/web/test/*.test.mjs services/ai-gateway/test/*.test.mjs services/sync-api/test/*.test.mjs tests/phone-ai.test.mjs
git diff --check
```

回归覆盖 Web 双客户端冲突副本、离线队列恢复、游标失败不推进、手机同步期间编辑、手机冲突副本、远端墓碑清理 AI 表，以及 AI 接受路径不自动调用同步。

## 设备执行前置

需要 API 20 可安装 HAP、授权调试安装条件、手机与本地 sync-api 的局域网地址和独立测试草稿。设备记录必须包含草稿 ID、操作 ID、基础版本、请求顺序、服务端版本、冲突副本 ID、游标，以及最终代码的长度和脱敏指纹；不记录完整思路、代码、密钥或用户数据。

设备矩阵：手机接受后检查无网络请求；手动同步后 Web 拉取相同 `main.cpp`；Web 修改后手机拉取；离线编辑恢复；两端并发编辑；同步期间继续编辑；远端删除后 AI 结果不可恢复。没有设备或真实 RDB 日志时，只能写“工程准备完成、设备待验”。
