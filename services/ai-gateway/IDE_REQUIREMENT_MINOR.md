# 需求单：IDE AI 辅助审查与语义补全

- 优先级：次要（P2）
- 所属：`services/ai-gateway`
- 状态：待排期
- 提出方：AlgoFlow Web / OpenHarmony IDE

## 背景

当前 IDE 已使用 CodeMirror 6 提供 C++ 语法高亮、关键字/STL/片段补全和本地基础规则诊断。CodeMirror 不具备 C++ 语义级补全、算法逻辑审查或编译器诊断能力，需要 AI Gateway 提供可选的、与编辑器解耦的辅助接口。

## 目标

为 IDE 提供两类可选能力：

1. 基于当前代码和用户思路的解释、风险和复杂度审查；
2. 用户主动触发的局部代码补全或修改建议。

## 范围

- 新增明确的 IDE 请求/响应契约，沿用现有 `mode`、`draft_id`、`draft_version`、`rule_version`、`visibility` 和来源引用语义。
- 审查结果至少包含诊断级别、行号/字符范围、问题说明、依据和建议；建议必须与用户代码分离。
- 补全结果必须限定为光标附近的局部片段，记录原始代码范围、建议文本、模型标识和规则版本。
- 支持 provider 未配置、provider 异常、超时和无效产物的分类错误。
- Web 与 OpenHarmony 客户端可以隐藏、接受或拒绝 AI 结果；AI 结果不得覆盖用户原文。

## 非目标

- 不替代 CodeMirror 6 的本地高亮、括号匹配、基础补全和基础规则检查。
- 不在本需求中实现 `clangd`、`clang-tidy` 或本地 C++ 编译。
- 不默认升级为 `full_solution`，不静默修正用户算法。
- 不在客户端保存 provider 密钥，不把模型原始日志或完整用户代码写入普通日志。

## 验收条件

- 请求显式携带 AI 模式、草稿版本、来源片段、输出类型和可见性。
- 每条审查建议都能定位到代码范围或明确标记为全局建议，并记录来源草稿版本。
- 局部补全不会返回完整题解、`main` 或未请求的新增算法步骤。
- 未配置 provider 返回 `AI_NOT_ENABLED`；provider 异常返回 `AI_PROVIDER_ERROR`；产物不符合契约返回 `INVALID_AI_ARTIFACT`。
- 至少补充正常、错误思路、提示注入、越权补解、超时、空结果和格式错误测试向量。
- 客户端拒绝或隐藏建议后，用户代码和既有 AI 产物保持不变。

## 依赖与风险

- 需要先确定默认模型、预算、隐私文案和第三方内容传输边界。
- 需要评审代码片段发送范围、限流、超时、审计字段和结果保留期限。
- 在 provider 和安全策略确认前，接口只能保持“AI 未启用”或返回分类错误，不能使用 Mock 冒充结果。
