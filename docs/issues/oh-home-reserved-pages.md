# [OH 首页] 补齐工作区预留能力与草稿管理

## 背景

OpenHarmony 端已经有可编辑的 IDE 页面，但工作区首页中的部分入口还没有对应的领域能力：归档/恢复、全部草稿独立列表、通知中心、历史版本统计和设置页面。目前首页只应展示真实的本地数据，不能用演示数字或模拟结果掩盖未完成能力。

## 目标

- 增加草稿归档与恢复的领域字段、RDB 迁移、同步契约和跨端行为。
- 提供独立的全部草稿列表，支持按状态筛选和稳定 `draft_id` 跳转。
- 提供历史版本查询和首页统计，明确版本来源与删除墓碑语义。
- 接入通知中心和设置页面，并补齐离线、未登录、同步失败等状态。

## 当前实现

- 首页入口已保留，但归档/恢复、通知、全部草稿、历史版本和设置仍为预留页面。
- 删除已复用 `DraftWorkspaceViewModel.deleteDraft` 与 RDB 墓碑同步，不在本 Issue 重复实现。

## 验收标准

- [ ] 归档草稿不会出现在默认最近草稿列表，但可恢复。
- [ ] 归档/恢复操作携带版本号、操作 ID，并能在 Web 与 OH 端同步。
- [ ] 全部草稿页面支持空态、加载失败、离线和冲突状态。
- [ ] 历史版本数量来自真实版本记录，不通过 `Draft.version` 伪造历史条目。
- [ ] 通知和设置页面具备可操作的错误恢复与返回路径。
- [ ] 完成 RDB 迁移、公共契约更新、双端回归测试和设备验证。

## 非目标

- 不引入 CRDT 或实时多人协作。
- 不把普通云同步描述为 OpenHarmony 分布式能力。
- 不改变 `Index.ets` 的代码编辑器交互契约。
